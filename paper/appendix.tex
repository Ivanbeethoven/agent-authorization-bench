\section{Protocol and artifact guide}\label{app:protocol}
\paragraph{Model-facing fields.}
AuthGateBench receives the user request, trajectory and proposed action. Under its no-signal condition the source has 700 records; the alternative signal condition reuses the same records. DelegationBench receives user instruction, context and candidate action. Jev Boundary receives the applicable policy, state and proposed action. The explicit-rule supplement carries its own policy, and the historical audit uses its archive policy. Exact-state exposure checks compare canonical serializations to prior project input manifests. The check detects previously seen wording, not pretraining contamination or semantic novelty. Jev development cases, duplicate sessions from the Jev deposit and external task suites do not enter primary totals.

\paragraph{DeepSeek review system message (verbatim).}
\begin{quote}\small\input{generated/system.tex}\end{quote}
The five output keys are \texttt{decision}, \texttt{basis}, \texttt{clarification}, \texttt{if\_yes} and \texttt{if\_no}. Basis values are covered, prohibited, missing fact and missing consent. Inapplicable clarification fields use the string \texttt{NA}. The current answer is scored directly, including when the explanation is internally inconsistent. Both DeepSeek stages use JSON-object mode, with output limits of 160 tokens for direct decisions and 320 tokens for structured review. The runner validates response keys, choice membership, completion status and reported model, retrying recoverable errors up to three attempts.

\paragraph{Legal and non-executable references.}
For DelegationBench the 149 resolved four-way responses comprise 69 execute, 71 request permission, eight request information and one refuse. The other seven cases all have a binary non-execution reference. Jev Boundary has 115 allow, 119 hold and 36 deny. AuthGateBench has 350 allow and 350 block. A false release on any of these datasets means reference non-execution followed by immediate approval. All 350 AuthGate blocks remain in that endpoint even though their prohibition severity is unspecified. The challenge's out-of-bound requests also test a stated authorization limit and have no independent severity annotation.

\paragraph{Cost accounting.}
The full public and supplementary runs used 1,372 direct calls per provider and 714 DeepSeek reviews. At the experimental rates, the costs were CNY 0.375434, 0.318105 and 0.694872 for Jev, DeepSeek direct and DeepSeek review, respectively. The numeric challenge used another 96 direct calls per model and 96 reviews. Two extra attempts were recorded in its review stage. Cost attribution uses the provider's returned token usage, including reported usage on retried responses. The Jev account increment agreed with the token-based estimate. DeepSeek wallet changes are read immediately and can lag. We used CNY 0.294 per million Jev input tokens; DeepSeek's off-peak input cache-hit, input cache-miss and output rates were CNY 0.02, 1 and 4 per million tokens, respectively. The three main methods used no GPT reviewer.

\paragraph{Reporting criteria.}
The primary denominator, legal-release denominator and exact-label denominator are reported separately. Paired comparisons preserve sample membership. Control selection never uses labels, and uncertainty calculations retain repeated family draws. The analysis distinguishes the public census, earlier exploratory observations, historical decisions and the prospective numerical challenge. The artifacts preserve source identifiers for inspecting counterexamples. These criteria implement the reproducibility, transparency and limitations principles described in the \href{https://neurips.cc/public/guides/PaperChecklist}{NeurIPS Paper Checklist Guidelines}.

\paragraph{Reconstruction.}
Run \texttt{full\_permission} with each provider, followed by \texttt{full\_permission\_review} with DeepSeek. Repeat this sequence with \texttt{numeric\_permission} and \texttt{numeric\_permission\_review} for the challenge. Use \texttt{full\_permission\_results.py} to reconcile receipts and compute paired decisions, \texttt{full\_permission\_analysis.py} for the sensitivity analyses and \texttt{paper\_assets.py} for tables and figures. The paper source directory contains a PowerShell build script. The distributed decision tables permit recalculating the main comparisons without access to an API credential.
